## 2. 啟動方式（本機，不碰正式資料庫）

開發與驗收用的是本機 Docker 裡的 MongoDB，資料庫名稱 `take-seat-dev`。`.env` 裡的正式資料庫沒有被連線或修改。

```bash
docker start take-seat-mongo
```

```bash
DATABASE_URL='mongodb://127.0.0.1:27027/take-seat-dev?replicaSet=rs0&directConnection=true' ADMIN_PASSWORD='<自訂一組本機用的密碼>' pnpm exec next start -p 3218
```

- 首頁：`http://localhost:3218/`（`next start` 需要先執行過 `pnpm build`）
- 領導團隊中控：`http://localhost:3218/console`，密碼是上面指令裡的 `ADMIN_PASSWORD`（只在本機有效）。
- 會員區：`http://localhost:3218/me`。本機沒有 LINE/Google 時，到 `/console/members/<會員>` 產生登入連結登入。

本機資料庫已有：39 位會員（由靜態名冊同步）、`2026-10-01` 例會（由現有 seed script 匯入的格狀座位表）。

## 3. 驗收清單

每一項的「通過」標準：畫面操作成功，重新整理後資料還在。

### 3.1 活動（`/console/events`）

- [ ] 新增一場今天日期的活動，建立後自動進入該活動的中控頁。
- [ ] 編輯活動名稱、地點、開始時間。
- [ ] 封存活動，並在「已封存的活動」還原。
- [ ] 在中控頁按「發布活動」，公開頁才打得開；取消發布後公開頁回到 404。

### 3.2 出席與代理（`…/attendance`）

- [ ] 對一位會員按「簽到」，再按「取消簽到」。
- [ ] 用「編輯」把一位會員改成「代理」並填代理人；清單顯示「代理・未到」。按「代理人到」後變成「代理・已到」。
- [ ] 把一位會員改成「請假」，上方統計同步變動。
- [ ] 新增來賓（含邀請人、執事）、編輯、簽到、移除。
- [ ] 「現場總人數」= 已到會員 + 已到代理人 + 已到來賓。

### 3.3 公開簽到與請假（手機）

- [ ] `/e/{活動}/check-in`：會員選姓名簽到；開始時間之後簽到會記為遲到。
- [ ] 同一頁「我是代理人」：選被代理的會員、填自己的姓名後簽到。
- [ ] 同一頁「我是來賓」：現場登記並簽到，後台來賓清單出現這位來賓。
- [ ] `/leave`：登記找代理／請假／會出席；後台出席表立即顯示。
- [ ] 登記尚未建立的週四，會自動建立該日期的活動草稿。

### 3.4 長冠軍之星（`…/polls`、`/e/{活動}/vote`）

- [ ] 建立投票、開放、結束、重新開放、刪除。
- [ ] 手機投票頁：點一位會員 → 選填一句好話（可點快速短語）→ 送出。
- [ ] 投票結束前可以改票；改票後後台票數跟著變。
- [ ] 後台看得到即時排名與好話清單（不顯示留言者）。
- [ ] 選了會員身份後，不能投給自己。

### 3.5 禮物抽獎（`…/gifts`、`/e/{活動}/lottery`、`/console/gifts`）

- [ ] 新增禮物（提供者選會員，或輸入其他名稱）、編輯、調整順序、刪除。
- [ ] 抽獎前台：領導團隊按「開抽」，隨機抽出一位已簽到的人；可「重抽」。
- [ ] 沒有領導團隊權限的裝置開前台，只能看結果，沒有開抽按鈕。
- [ ] 事後在後台修改得主、修改提供者；舊的抽獎結果保留在紀錄中。
- [ ] 抽獎池設定（會員／來賓／代理人、是否排除已中獎者）儲存後生效。
- [ ] `/console/gifts` 禮物總帳列出跨活動的禮物、提供者與得主。

### 3.6 綠燈會員（`/console/scorecard`、`/me/scorecard`）

- [ ] 在 `/console/scorecard/import` 上傳 BNI Connect 匯出的 PALMS `.xls`。
- [ ] 檢視頁顯示期間、會員數、例會次數，並列出對不上的姓名；為每一筆選擇對應會員、新增會員或略過。
- [ ] 確認匯入後，總覽出現各會員分數與燈號。
- [ ] 同一期間再匯一次：新檔成為目前版本，舊檔留在歷史。
- [ ] 匯入第二個期間後，總覽出現逐期變化與「上期 → 本期」。
- [ ] 在計分規則頁修改門檻或級距，儲存為新版本並啟用，燈號隨之重算。
- [ ] 會員區 `/me/scorecard` 只看得到自己的燈號。

### 3.7 場地與座位（`/console/venues`、`…/seating`）

- [ ] 新增場地、編輯、刪除。
- [ ] 由範本建立配置（教室、劇院、圓桌、U 型、口字、島型），在編輯器拖曳物件、改座位數、儲存。
- [ ] 在活動的「座位」分頁選一個配置建立座位表，把人排進座位並儲存。
- [ ] 活動中控、公開活動頁、會員今日頁都顯示同一張平面圖；公開頁可用姓名找座位。

### 3.8 會員與設定

- [ ] `/console/members`：新增、編輯、停用、恢復會員；「從靜態名冊同步」。
- [ ] 「未分類名單」可設為會員或標記為非會員。
- [ ] `/console/settings/roles`：新增、編輯、結束、刪除職位任期。
- [ ] `/console/settings/audit`：上面的操作都有紀錄。
- [ ] `/me/profile`：會員修改自己的產業、公司、介紹、目標客戶。

## 4. 新舊頁面並存時的行為

- 新頁面的出席資料存在新的 `Participation`。為了讓舊頁面（`/w/[slug]`、Excel 報表）看到一致的結果，新頁面寫入時會同步回寫舊欄位。
- 舊頁面的登記（`/pre-leave`、舊公開頁的「抵達」）會在下次開啟新頁面時帶入，但只會填入新頁面還沒動過的紀錄。
- 舊公開頁按「取消抵達」不會回寫到新的出席紀錄，需要在新的出席頁取消。

## 6. 上線到正式環境前要做的事

需要使用者明確同意後才執行：

1. 把新的資料模型推到正式資料庫（`prisma db push`）。這次的變更全部是新增 collection 與選填欄位，不會改動既有資料。
2. 在正式環境從靜態名冊同步會員（`/console/members` 的按鈕）。
3. 設定 `ADMIN_PASSWORD`，並處理 ARC-006 §3 列出的安全問題。
